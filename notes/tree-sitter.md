## 파싱(Parsing) & 파서(Parser)
### 파싱(Parsing)
- 일련의 문자열(텍스트)을 의미 있는 최소 단위(토큰)로 쪼개고 그 단위들이 정해진 문법 규칙에 맞는지 분석하여 구조화하는 과정 전체를 의미
- 사람이 영어 문장 "I ate an apple"을 들었을 때 뇌 속에서 I(주어) + ate(동사) + an apple(목적어)로 문장 구조를 파악하고 의미를 이해하는 과정이 파싱
- 컴퓨터에서의 파싱: 단순 텍스트에 불과한 소스 코드("int a = 10;")를 컴퓨터가 이해할 수 있도록 "변수 선언문이며 타입은 int, 이름은 a, 값은 10"이라는 구조적 데이터(트리 형태)로 해석해 내는 작업
### 파서(Parser)
- 파싱 작업을 직접 수행하는 프로그램이나 모듈(엔진)
1. 어휘 분석 결과를 전달받음: 소스 코드를 단어 단위(키워드, 식별자, 연산자 등)로 쪼갠 토큰 리스트 받음
2. 문법 검사: 규칙에 어긋난 문법이 없는지 확인
3. 트리 구조(AST) 생성: 문법 구조를 컴퓨터가 처리하기 쉬운 추상 구문 트리 형태로 구축
```Plaintext
[ 소스 코드 ]
  "a = b + 1"
      ↓
[ 1단계: 어휘 분석 (Lexer) ]
  토큰화: [식별자: a], [대입: =], [식별자: b], [더하기: +], [숫자: 1]
      ↓
[ 2단계: 구문 분석 (Parser) ]
  문법 규칙 검사 및 트리 구조(AST) 생성
      ↓
[ 파싱 결과 (AST) ]
       (=)
      /   \
    (a)   (+)
          /  \
        (b)  (1)
```

## Tree-sitter
- 소스 코드를 분석하여 구문 트리를 만들어 주는 고성능 구문 분석(Parsing) 도구 및 라이브러리
- 엔진과 언어별 문법 규칙이 완벽히 분리된 2층 구조로 설계되어있음
- 파서 엔진(tree-sitter)
    - 문자열 데이터를 받아 트리를 생성하고 검색 및 노드 탐색 API를 제공하는 공통 실행 엔진
    - C 언어로 작성되어 극도로 빠르고 Python 바인딩을 통해 호출
- 언어 팩(tree-sitter-c-sharp)
    - C#의 키워드(class, namespace 등), 연산자, 식별자, 문법 구조 규칙이 정의된 전용 C 라이브러리/C++ 파서 모듈
- 작동 방식
    - 엔진(Parser)에 C# 언어 팩(Language)를 장착해야 C# 전용 파서로 동작
    - 어떤 언어 팩을 장착하느냐에 따라 엔진 하나로 모든 소스코드를 동일한 방식으로 다룰 수 있음

### 정규식 대신 Tree-sitter 사용하는 이유
1. 제네릭 및 중첩 괄호 균형(`<>`, `{}`)
    - `List<Dictionary<string, List<int>>`처럼 괄호가 중첩된 경우 시작과 끝의 짝을 제대로 맞추지 못하고 탐욕적 검색 오류 일으킴
        - 탐욕적 검색: 패턴에 일치할 수 있는 가장 긴 문자열을 한 번에 가져오려는 기본 성질
        - 정규식 반복 기호들은 기본적으로 탐욕적으로 동작(일단 가장 큰/긴 덩어리 덥석 물고 보는 성질)
            → 패턴 만족하는 지점 찾았을 때 바로 멈추지 않고 문장의 끝까지 훑으며 최대한 많은 문자 포함하려 함
        - 탐욕적 검색 오류 발생하는 이유: 한 줄에 코드 구분이 여러 개 있는 경우에 첫 번재 `<`부터 마지막 `>`까지 하나의 괄호 쌍으로 묶어버림
    - Tree-sitter는 문맥 자유 문법 기반이므로 중첩 깊이에 상관없이 완벽한 트리 짝 맞춤
        - 문맥 자유 문법: 어떤 표현이나 문법 규칙을 적용할 때 주변 문맥에 상관없이 특정 기호를 언제나 정의된 규칙대로 바꿔 쓸 수 있는 문법 시스템
        - 문맥에 자유롭다는 것: a + b라는 식을 쓴다고 가정
        - 이 a + b는 리턴문 안if 문 안에 있다고 해서 a + b를 a + (b) 형태로 바꿔 적어야 하거나 함수 인자로 쓰인다고 해서 + a b처럼 문법 구조 자체가 바뀌지 않음
        - 즉 주변 환경(if문 속인가, 함수 안인가)이 무엇이든 상관없이 [값] + [값]이라는 독립된 규칙 그대로 사용할 수 있음 → 이게 문맥 자유
- 다중 줄 처리
    - 함수 선언이나 람다 식이 여러 줄게 걸쳐 나뉘어 있을 때 정규식은 줄바꿈 처리가 복잡해지고 전후 문맥 놓치기 쉬움
    - 파서는 줄바꿈을 공백 토큰으로 처리 → 다중 줄 구조도 하나의 노드로 묶어냄
- 주석 및 문자열 내부 예외 처리
    - 주석이나 문자열 리터럴 내부에 포함된 코드 키워드를 실제 코드 구조로 오인하기 쉬움
    - tree-sitter는 어휘 분석 시점부터 이들을 comment, string_literal 노드로 격리 → 오탐 발생X

### 기본 사용법
- 소스코드를 바이트로 변환하여 입력하는 것이 핵심
```python
import tree_sitter_c_sharp as tscsharp
from tree_sitter import Language, Parser

# 1. 언어 팩 로드 및 파서 인스턴스 생성
CSHARP_LANGUAGE = Language(tscsharp.language())
parser = Parser(CSHARP_LANGUAGE)

# 2. C# 소스코드 준비 (반드시 bytes 포맷이어야 함)
source_code = b"""
namespace GameDev
{
    public class Player : Monobehaviour
    {
        private int hp = 100;
    }
}
"""

# 3. 구문 분석 실행 -> AST/CST 생성
tree = parser.parse(source_code)
root_node = tree.root_node

print(root_node.type)  # 출력: compilation_unit
```

### 핵심 노드 개념과 탐색 메서드
- 노드: 트리를 구성하는 모든 단위
- `node.type`: 노드의 문법적 유형 나타내는 문자열(예: `class_declaration`, `indentifier`, `modifier`)
- `node.named_children`: 주석, 쉼표, 세미콜론 같은 의미 없는 구문 기호를 제외하고 의미를 가진 자식 노드들만 배열로 반환
- `node.child_by_field_name("name")`: 문법적으로 이름이 부여된 특정 자식을 직관적으로 가리킴
- `node.text.decode("utf-8")`: 해당 노드가 소스코드에서 차지하는 실제 텍스트 영역 슬라이싱하여 추출
- `node.parent`: 현재 노드를 감싸고 있는 바로 위의 부모 노드로 역방향 탐색

### CST(구체 구문 트리) vs AST(추상 구문 트리)
- 프로그래밍 언어로 작성된 코드를 컴퓨터(파서/컴파일러)가 이해하기 위해 트리 구조로 변환한 결과물
- Tree-sitter는 CST를 생성함

**AST(추상 구문 트리)**
- 추상적 이라는 이름처럼 중요한 뼈대만 남아있음
- 소스코드의 문법 기호나 키워드를 제거하고 의미 있는 데이터 구조만 남긴 트리
- 단점: 원본 코드의 공백이나 괄호 위치 같은 세부 형태는 복원하기 어려움
- 컴파일러 내부 연산용

**CST(구체 구문 트리)**
- 구체적 이라는 이름처럼 코드의 모든 구체적인 요소 다 살아있음
- 소스코드의 모든 글자(공백 제외), 중괄호, 세미콜론, 주석까지 100% 트리의 노드로 유지
- 단점: 트리 노드가 너무 많아지고 구조 매우 복잡
- 코드 포매터(탭 간격이나 띄어쓰기 맞춰주는 정돈 도구), 린터(코드의 오타 지적해주는 도구)

```PlainText
[AST: 추상 구문 트리]             [CST: 구체 구문 트리 (Tree-sitter)]
   ClassDeclaration                  class_declaration
   ├── name: Player                  ├── "public" (modifier)
   └── base: Monobehaviour           ├── "class" (keyword)
                                     ├── "Player" (identifier)
                                     ├── ":" (punctuation)
                                     ├── "Monobehaviour" (identifier)
                                     ├── "{" (punctuation)
                                     └── "}" (punctuation)\
```

### 주요 C# 노드 타입 예시

- C# 코드 파싱했을 때 구성되는 대표적인 노드 타입 구조

| 노드 타입 (`node.type`) | 설명 | 필드 / 특징 예시 |
| --- | --- | --- |
| **`class_declaration`** | `class` 선언 전체 블록 | `name` 필드로 클래스명 지정, `body` 필드로 `{}` 내부 지정 |
| **`base_list`** | 상속받는 클래스/인터페이스 목록 (`: Mono, IPointer`) | 별도의 필드명이 제공되지 않음. 자식 노드들을 순회(`children`)하여 탐색해야 함 |
| **`declaration_list`** | 클래스나 구조체 내부의 본문 영역 (`{ ... }`) | 메서드, 필드, 프로퍼티 선언 노드들을 포함 |
| **`modifier`** | 접근 제어자 및 형태 수식어 | `public`, `private`, `static`, `override`, `sealed` 등 |
| **`method_declaration`** | 메서드 선언 블록 | `type`(반환타입), `name`(메서드명), `parameters`(매개변수) 필드 제공 |

### 함수

**`field_name_for_chil(i)`**
- 부모 노드의 `i`번째 자식이 해당 문법 구조에서 어떤 역할(필드 이름)을 하는지 알려주는 함수
